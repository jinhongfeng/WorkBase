# WorkBase 功能与界面检查（2026-11-05）

## 结论

当前产品已有统一的绿色视觉、清晰的笔记编辑区和可用的本地记录基础，设计感中等，AI 模板感偏轻。还不能视为功能完整、可以发布的 V1。最需要投入的是可靠性和工作流完整性，其次是首页信息层级，不需要推翻配色重做。

本轮是检查交付，没有修改业务代码、设计规范、迁移或用户数据。依据当前源代码、实际 Electron 窗口及本轮构建结果判断；历史报告不作为本轮验证通过的依据。

## 检查范围

- 先读取 `docs/DESIGN.md`、阶段计划、项目规则，再检查主进程、IPC、仓储、注册表和主要页面。
- 使用真实 Electron、preload 与 SQLite，测试数据放在 `temp/audit-20261105/profile`，没有使用浏览器模拟接口。
- 1360×860 浅色查看首页、待办、笔记、专注、设置、助手、账单；1080×700 深色查看首页、笔记编辑器、雅思、媒体库、Skill 库、习惯和更多面板。另查看大窗口深色首页、设置。不是所有页面、主题、尺寸的完整交叉验收。
- 手动验证笔记创建、编辑、保存、重启留存；待办创建及重启留存；首页卡片调整顺序、保存、离开后返回；专注启动、离开后返回。
- 未配置真实 AI 或邮箱，没有发出真实对话、邮箱同步、远程媒体下载请求。

## 应优先修复的问题

### P1：专注计时离开页面后丢失（已复现）

开始 25 分钟专注，计时到 24:48；进入笔记，再从命令面板返回专注，显示 25:00、准备开始，未提示原计时被取消。

原因：`src/renderer/src/features/focus/module.tsx:12` 起将剩余时间和运行状态保存在页面组件；路由卸载后状态和定时器一起销毁。当前逐秒减一还可能受后台节流、休眠影响，但本轮未测量这一部分。

建议：运行状态移出页面，以结束时间计算剩余时长；切页继续计时，暂停记录剩余时长，并提供跨页面的运行提示。重启/休眠如何恢复需要明确行为。验收必须包括“专注期间进入笔记写作再返回”。

### P1：首页卡片排序保存后重新进入失效（已复现）

管理卡片，用排序手柄的右方向键把月历移到年度活动之后，点完成，当前页面正确；进入设置再返回首页，恢复为月历在前。应用重启后同样恢复默认顺序。

原因：`src/renderer/src/features/dashboard/module.tsx:89` 用注册表顺序过滤已存 key，丢弃了存储数组的顺序。`dashboard.css` 还有 `grid-auto-flow: dense`，混合跨列尺寸时可能让视觉顺序与保存顺序不同，后者尚未单独复现。

建议：按保存数组逐项解析可用卡片，过滤失效 key 并去重；保证不同尺寸下顺序的含义一致。只做针对性回归：换顺序、保存、切页、重启、取消编辑。

### P1：“导出备份”不是完整备份（代码确认）

`src/main/ipc/assets.ts:22` 只执行 WAL checkpoint 后复制 `.db`。没有复制 `files` 中的笔记图片、媒体、Skill 文件和壁纸。新电脑仅恢复数据库，无法还原这些实际文件。

建议：按规范交付数据库一致性快照与文件目录，包含旧版附件目录的兼容内容；提供明确的恢复说明，并验证一篇带图片笔记、一项媒体和一个 Skill 能在另一数据目录打开。界面补充备份范围、完成状态与体积。恢复入口是额外的产品改进建议，当前规范主要要求导出全量备份。

### P1：AI 仍是独立、临时的聊天页面（代码确认）

`features/ai/module.tsx:21` 的会话仅存于组件状态；切页会丢失对话。没有会话库、重命名、停止生成、规范要求的 380px 抽屉及笔记/待办/账单上下文动作。“保存到笔记”是手动归档，不能替代会话持久化。

`src/main/ai/client.ts` 中的超时在 fetch 返回响应头后就清理，后续流读取缺少覆盖完整生命周期的超时与用户取消。此结论来自源码，没有用真实服务复现断流。配置也未提供规范中的 maxTokens。

建议：先完成历史、停止/取消与完整请求生命周期，再补最有用的“笔记提取待办，确认后写入”与“账单聚合分析”。优先让 AI 能处理工作台中的内容。

### P2：记录核心还有明显缺项（实测与代码确认）

| 位置 | 当前情况 | 需要补齐 |
| --- | --- | --- |
| 待办 | 输入“明天 10:00 提交审查稿”后仍位于待安排，截止日期为空；有日期与优先级表单 | 自然日期识别、今日/本周/全部/已完成筛选、已有任务编辑、拖拽排序 |
| 待办仓储 | 有 sort 列，列表查询不按 sort 排序，没有 reorder 通道 | 排序界面、IPC 与查询形成完整链路 |

## 界面是否有设计感，AI 味道是否浓

**主观评价：已有稳定的工具界面气质，AI 味道偏轻，但精细程度和内容主次仍有提升空间。** 系统字体、单一绿色强调、短动效和少装饰是合适的；不需要为了“去 AI”换成另一套流行模板。

值得保留：

- 笔记的列表/编辑分区清楚，正文区域安静，窄窗口仍能使用。
- 主色、按钮、图标、浅深主题总体一致；没有大面积渐变、宣传式标题或装饰插画。
- 更多面板有分组，图钉与功能入口分开；未配置 AI 有明确设置入口。

最值得改的视觉与交互：

1. **首页首屏任务优先。** 当前月历和年度活动先占一大行，1080×700 下今日待办在首屏之外。建议把快速记录与今日待办放在上部，将日历/活动统计作为较次要的可选区。保留用户的自定义排序，不强行覆盖。
2. **删减低价值说明卡片。** 待办右侧的“优先级说明”重复下拉框含义；专注“节奏建议”是通用说明。可收成帮助提示，给实际任务、计时状态与历史记录更多空间。
3. **统一空状态。** 笔记/媒体库居中引导，Skill 库靠左上，雅思空库仍保留多组筛选和四个 0。统一主操作的位置、间距和层级；无内容时逐步呈现次要控制，减少重复入口。
4. **收敛页面标题与留白节奏。** 媒体库 22px、通用页 26px、首页 28px，部分差异合理，但顶部内边距与说明行也各自变化。以通用页壳统一基线，编辑器与对话保留各自必要布局。
5. **笔记工具栏做渐进显示。** 窄窗口仍放 H1–H4 和二十余个工具。把低频标题级别、插入类操作收进菜单，常用格式保持直接可点。
6. **空数据图表少画无意义坐标。** 首页 0 分钟时仍展示完整坐标轴，雅思空库仍有四项零值统计。短文案加一个主操作能让首次体验更明确。

“绿色背景 + 白卡片”仍有常见工作台模板痕迹，但问题主要在重复卡片和默认填充说明。增加渐变、大插画、复杂动效不会改善日常使用。

## 规范与当前成果的差异

- DESIGN 第 7 节仍规定紫蓝强调色、40px 标题栏与 64px 图标轨；实现为绿色、46px 标题栏，宽屏 152px 侧栏。
- DESIGN 第 8 节笔记要求 Markdown 双栏，当前采用富文本/源码切换；AI 要求抽屉与 Ctrl J，当前为整页与 Ctrl 8。
- DESIGN 第 5 节的 AI/数据源预留迁移表仍旧，但第 8 节年度活动已明确后续从最大编号递增，替代旧预留。因此不能把 008/009 描述为当前未解决的运行时冲突，也不能重复添加同编号迁移。
- README 仍写账单隐藏、仅 AI 发起网络请求，已经落后于账单、媒体和壁纸实现。

后续实现应先由审批方统一冲突条目，保留现有绿色和已完成能力；本轮仅记录，没有自行改 DESIGN，也没有修改已执行迁移。具体记录追加到 `temp/blocker.md`。

## 建议的实施顺序与验收

1. **可靠性小阶段**：完整备份、专注跨页计时、首页排序；验收只覆盖相应主路径与返回/重启，附最小恢复验证。
2. **记录核心阶段**：待办编辑/日期/筛选/排序，跨模块搜索、笔记长列表与保存失败保护。先补高频能力。
3. **AI 工作流阶段**：会话留存、停止与错误恢复，再做笔记提取待办、账单聚合分析。
4. **视觉收敛阶段**：首页任务优先、删除说明卡、统一空态与工具栏；沿用现有主题。
5. **外部数据与发布阶段**：通用邮件、数据源按原阶段补齐；验证真实账户与 AI、安装包、性能指标，再判断 V1 是否发布。

以上是依赖顺序建议，不表示本次开始跨阶段开发。多端同步、移动端、团队与插件市场仍是 V1 非目标，不计作当前缺陷。
