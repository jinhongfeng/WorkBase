# 页面布局与交互收敛 — 审查与交付（2026-11-06）

审批方：小 O。实现方：本地 Codex（`codex-cli 0.166.0`，`gpt-6.1-sol`）。
范围：`src/renderer/src` 全部页面与共用骨架。不改数据流、IPC、迁移、依赖与 `docs/DESIGN.md`。

## 结论

全站存在三类布局问题：**同一动作有 2–3 个入口**、**破坏性操作紧贴主操作**、**页面骨架各写一套**。本轮按「一个页面只有一个主操作」的规则收口，共改 19 个文件、涉及 11 个页面与 2 个共用骨架组件。核心业务流程（记笔记、待办、账单导入、雅思生成/复习、媒体入库、Skill 编辑、AI 会话）均未改动，只移动/合并入口。

## 审查方法

1. 逐页读 JSX 与同目录 CSS，按「同屏是否有重复入口 / 主次是否颠倒 / 骨架是否一致 / 空态是否给出路」四项判定。
2. 构建后用真实 Electron（隔离 userData）走 CDP，按 1360×860 逐页截图，改前改后各一轮；空态与有数据态分别取证。

## 二、优化后的整体布局规范

1. **骨架**：功能页一律 `.page`（最多 1100px，内边距 28/32/48）+ `.page-head`（24px 标题 + 13px 灰色描述 + 右侧操作区）。首页、设置、笔记、Skill 库、对话保留各自必要的分栏，但标题与内边距对齐同一基线。
2. **主操作唯一**：一屏只有一个 primary。空态与页头不会同时给同一个动作的 primary —— 空库时主操作下沉到空态，有数据时回到页头。
3. **操作位置**：页面级主操作在右上；列表级操作在列表头；行级操作 hover 出现；破坏性操作必须离开主操作区，并二次确认。
4. **空态**：一句引导 + 一个主操作；空库时隐藏所有依赖数据的控件（统计、筛选、分组条），逐步呈现次要控制。
5. **按钮体系**：全站只用 `.button`（primary / secondary / ghost / danger，含 `sm`、`icon`）。首页自有按钮类已删除。

## 五、残留问题（明确未做）

1. **笔记编辑器在壁纸态下可读性不足**：`layout.css` 在壁纸激活时把 `--workspace-canvas` 设为 `transparent`，正文直接压在照片上。属并行壁纸工作流的 tint 议题（当前 `--wp-content-tint` 48%），本轮未改；建议给编辑画布一层 `color-mix(--surface 90%, transparent)` 兜底。
2. **首页卡片高度不齐**：masonry 按自然高度排，短卡（今日待办）旁边会有留白，需要统一卡片最小高度才能消除；本轮只保证不复现「整列空洞」。
3. **待办行内编辑、自然日期解析**仍未实现（属功能缺口，不在本轮布局范围）。
4. 工作区同时有另一条工作流在改 `layout.css`/`tokens.css`、`features/focus/*`（沉浸专注、视频壁纸）。本轮只做布局与入口收敛，未回退、未修改它们的逻辑；`settings/SettingsPage.tsx` 中视频壁纸预览属该工作流，本文档不计入本轮改动。
