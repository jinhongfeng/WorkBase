# 页面布局与按钮可用性审查（2026-11-07 14:5x）

范围：11 个可见页面（首页、笔记、待办、雅思、习惯、专注、Skill 库、媒体库、支付宝账单、智能助手、设置）、设置四个分区、全局导航与浮层（标题栏搜索、更多面板、命令面板、确认弹窗、沉浸专注四场景）、首页卡片编辑态。

方法：读当前源码与样式表，取 CSS 声明值为尺寸证据；与当日早间的实测文档（`BUTTON-LAYOUT-AUDIT-2026-11-07.md`、`UI-REFACTOR-2026-11-07.md`）对照；用当日截图核对结构（截图仅用于版式确认，不作尺寸依据）。本次未启动应用实测，文中的 px 均为声明值，标注「实测」的沿用早间数据。

---

## 1. 结论

组件层已经统一（`PageHeader` / `StatCard` / `Meter` / `BarList` / `Pager` / `Alert`），全局按钮基准 34px 合理，页面骨架与导航模型与 `DESIGN.md` 第 7 节一致。剩余问题集中在三类，且都不是「风格不好看」，而是可量化的可用性缺陷：

1. **局部小点击区**：仍有 20–28px 的目标，且多出现在高频或破坏性动作上（首页文本链接、AI 会话行、常用区编辑按钮、雅思发音、分页）。
2. **同屏重复信息**：页头 meta 与统计卡重复、表格合计与统计卡重复，占用首屏却不再提供新信息。
3. **样式层重复定义**：同一批类名在 `ui.css` / `components.css` / `layout.css` 各写一份，生效值由 `@import` 顺序决定；`features.css` 还残留整段旧版页面样式，靠选择器权重压住。

统计：高 5 项、中 12 项、低 8 项。

### 判定基准

| 用途 | 目标尺寸 | 依据 |
|---|---|---|
| 常规文字按钮 | 34px 高 | `ui.css` `.button`，现有实现 |
| 次级/栏内按钮 | 29–30px 可接受 | `.button.sm`、`.segmented`，需有成对留白 |
| 高频或破坏性图标按钮 | ≥32px | 20–22px 图标需包在 32–34px 命中区内（待办 `.check` 已按此改到 34×34，可作为范本） |
| 密集网格（日历、打卡、热力图） | ≥27px 且要有表头或文字提示 | `DESIGN.md` 第 7 节「密集格按任务单独验收」 |
| 危险动作与高频动作的间距 | ≥12px，或不同分组 | 防止手快误点 |

## 2. 高：可用性或误操作风险

### H1. 笔记文档栏：删除键紧贴置顶键，均为 29px 纯图标

- 位置：`features/notes/module.tsx:295-310`（`notes-document-bar`），样式 `features/notes/notes.css:66`（`.notes-document-actions { gap: 2px }`）。
- 现象：右侧依次是「大纲」（带文字）、置顶（纯图标）、删除（纯图标）。两个纯图标按钮 29×29px，间距 2px，都只有 hover 才出现 `title`。删除是全页最不可逆的动作，却是这一组里最靠右、最容易被顺手点到的位置。
- 建议：把删除移出该组，放到文档栏最右侧并留 ≥16px 间距（或收进一个「更多操作」按钮，与 Skill 详情的做法一致）；置顶保留原位。确认框保留，确认文案已带对象，不必改。
- 依据：`DESIGN.md` 第 7 节「列表项 hover 才显示次要操作」是允许的，但破坏性动作不应与常用开关共享同一命中带。

### H2. 首页文本链接的点击区只有约 20px 高

- 位置：`features/dashboard/dashboard.css:140-149`（`.home-link`），无高度、无内边距，字号 12px，正文行高 1.68 → 高度约 20px。
- 出现处：首页「全部待办」「打开/写今日日记」「重试」，账单三张首页卡的「查看账单」，年度活动读取失败的「重试」（`dashboard/module.tsx:432,460,595`、`bills/DashboardCards.tsx:41,45`、`ActivityCalendar.tsx:177`）。
- 建议：`.home-link` 加 `min-height: 32px; padding-inline: 8px; margin-inline: -8px;`，靠负外边距保持文字视觉位置不变。这是本报告里改动最小、收益最直接的一条。
- 备注：「编辑常用」已经通过 `.home-edit` 补到 30px（`dashboard.css:348`），说明类名已知问题，只是 `.home-link` 本身没补。

### H3. 智能助手会话列表行高 28px

- 位置：`features/ai/assistant.css:89-100`（`.chat-thread { height: 28px; line-height: 28px }`）。
- 现象：这是对话页唯一的导航列表，行高比全局列表行（40px）和常规按钮（34px）都低一档，长标题还要靠 `title` 才能看全。
- 建议：`min-height: 34px`，`padding-inline: 10px`，行内改两行结构（标题 + 时间/条数）或保持单行但放大命中区。会话条目本身不多，不存在空间压力。

### H4. 首页常用区编辑态的按钮 23×23，且「移除」无撤销

- 位置：`features/dashboard/dashboard.css:350-352`（`.home-favorite-actions button { width: 23px; height: 23px }`），触发点 `Favorites.tsx:59-69`。
- 现象：编辑态在快捷入口下方叠一排「前移 / 后移 / 移除」，三个按钮 23px，且移除立即写库（`save(pinned.filter(...))`），没有确认也没有撤销。
- 建议：按钮改 32×32、整组高度不低于 32px；移除改为先更新界面再给一条带「撤销」的 toast（`window.toast` 目前只有文本，可复用现有 toast 加一个操作按钮，或退回「确认弹窗」）。前移/后移在首尾已禁用，保留。
- 说明：这里的操作对象是「导航配置」而非数据，误触成本低于笔记删除，但按钮尺寸已低于图标类目标的底线。

### H5. 设置 → 数据与备份：三个按钮同排，「会重启应用」的动作无二次确认

- 位置：`features/settings/SettingsPage.tsx:251-261`，样式 `settings.css:108`（`.preferences-actions { flex-wrap: wrap }`）。
- 现象：`打开数据目录`（只读、无害）、`更改保存位置`、`用回默认位置`（后两者复制数据后**自动重启**）在同一行、同一视觉权重。当前只有下方一行说明小字提示会重启。
- 建议：拆成两组。第一组「数据目录」只放「打开数据目录」；第二组「迁移目录」放两个会重启的动作，并在点击后加确认弹窗（写明：会复制现有数据、保留原目录、随后重启）。这与 `DESIGN.md` 第 7 节「破坏性操作二次确认」的口径一致，迁移虽不算删除，但会中断当前工作。

## 3. 中：层级、归属与冗余

### M1. 待办 / 习惯：页头 meta 与统计卡是同一个数字

- 位置：`features/todos/module.tsx:118-133`（meta 显示「N 未完成 · M 已完成」，第一张 `StatCard` 又是「未完成 N」），`features/habits/module.tsx:82-101`（meta「N / M 今日完成」，第一张卡又是「今日完成 N/M」）。
- 建议：删除页头 meta 的完成数，或把 meta 改成统计卡没有的信息（如「最近更新 14:32」）。习惯页第一张卡已经带 `Meter`，信息比 meta 完整，优先删 meta。
- 依据：`DESIGN.md` 第 7 节「页面标题下方不设说明小字」，meta 重复计数属同类问题。

### M2. 账单：表格合计与「范围」统计卡重复，同屏 5 张金额卡

- 位置：`features/bills/module.tsx:251-257`（范围收入/支出/结余三卡）与 `279-282`（`tfoot` 再写一次收入/支出/净额）；加上 `236-246` 的本月两张卡，一屏 5 张金额卡 + 2 个 `rule-label`。
- 建议：`tfoot` 改为「本页小计」，与「所选范围」区分口径；或去掉 `tfoot` 的净额、只留本页合计。5 张卡不是错，但两张本月卡与三张范围卡之间缺少视觉分隔，读者容易把「本月支出」也当成受筛选影响（见 M3）。
- 依据：`DESIGN.md` 第 8 节要求「本月收支独立显示」，独立的前提是让读者看出它不受范围筛选影响。

### M3. 账单：「所选范围 · 全部」标签与筛选器的选中态重复

- 位置：`features/bills/module.tsx:247-250`，顺序为「`rule-label`：所选范围 · 全部 → segmented（当前项高亮）→ 三张范围卡」。
- 现象：标签已经把当前范围写了一遍，紧接的分段控件又用高亮写一遍，两者信息完全相同；而「本月收支」上方那条 `rule-label` 承担的是分组职责，两条标签看起来同级，实际一个是分组、一个是状态复述。
- 建议：删除「所选范围」标签，范围区直接由筛选器承担标题；「本月收支」保留标签作为分组，并可加一句「不受下方筛选影响」的弱提示。这样概览区从「2 标签 + 3 控件组」收敛到「1 标签 + 2 控件组」。
- 备注：筛选器紧邻它所影响的统计，位置本身是对的，不需要上移。

### M4. 雅思：唯一的「删除学习包」藏在只有一个条目的下拉菜单里

- 位置：`features/ielts/module.tsx:234-236`（`ActionPopover` 只有一项），`ielts.css:41`。
- 现象：为单个动作套一层浮层，多一次点击；`ActionPopover` 的设计前提是「多个低频动作」。
- 建议：改为学习包下拉框右侧一枚 34px 的危险图标按钮（`aria-label="删除学习包"`，`Trash2`），点击后仍是现有确认框（确认框已带包名，符合要求）。若将来加「重命名学习包」，再恢复成菜单。

### M5. 雅思：生成表单占据首屏最高权重，高频任务在它下面

- 位置：`features/ielts/module.tsx:157-202`（`ielts-gen` 卡片，位于页头之后、统计与词条之前）。
- 现象：生成是一次性/低频动作，浏览与复习是日常动作；现在低频表单占掉首屏最上方的整块，统计与词条被推到折叠线以下（1080×700 尤其明显）。
- 建议：生成卡默认收起为一行（标题 + 当前设置摘要 + 「展开」），展开后保持现有表单布局；或把生成卡移到统计与学习库之后、页尾。两者都不改变生成逻辑。
- 依据：`DESIGN.md` 第 7 节「不参考仪表盘大屏的密集卡片」，首屏应留给当前任务。

### M6. 雅思：分段控件被压到 26px

- 位置：`features/ielts/ielts.css:43-47`（`.ielts-gen-controls .segmented button, .ielts-library-bar .segmented button { height: 26px }`）。
- 现象：全局 `.segmented button` 是 29px（`ui.css:96`），这里为了塞进一行再压 3px；词条筛选有 4 个选项，是全页点击频率最高的一组控件。
- 建议：恢复到 29px，必要时让「内容类型」与「生成设置 / 生成学习包」分两行（`.ielts-gen-controls` 已经是 `flex-wrap: wrap`）。

### M7. 雅思词卡发音按钮 26×26，且默认不可见

- 位置：`styles/features.css:90`（`.icon-btn { width: 26px; height: 26px }`），显示逻辑 `ielts.css:80-84`（`opacity: 0`，hover/focus-within 才 1）。
- 现象：发音是词卡唯一的行内动作，26px 已偏小，还要先把鼠标移到卡片上它才出现；触屏分支有兜底（`@media (hover: none)`），但桌面端首次发现成本高。
- 建议：32×32；或者保持 hover 显形，但在卡片右下角常驻一个更弱的静态图标槽（点击区不变），避免「不知道有这功能」。

### M8. 媒体库：返回入口占用 `PageHeader` 的 kicker 槽位

- 位置：`features/media/MediaPage.tsx:242-244`（把 `Button` 传给 `kicker`），`media.css:6-8` 逐条覆盖 `.page-kicker` 的字距、伪元素。
- 现象：kicker 的语义是 11px 大写分类标签，现在塞一个 29px 按钮进去，再在页面 CSS 里反向覆盖它的小写、字距、`::before` 装饰线。能看，但结构上是借用。
- 建议：给 `PageHeader` 增加 `back?: { label, onClick }` 属性，由组件自己渲染在标题上方或左侧，媒体页删掉这四条覆盖规则。这样后续再有二级页（如分组内页）可直接复用。

### M9. 媒体库：批量管理是与筛选/搜索同级的模式开关，却混在工具栏里

- 位置：`features/media/MediaPage.tsx:261-288`；进入后 `.media-toolbar.is-selecting` 变成 sticky 卡片（`media.css:70`），一行里出现「类型筛选 + 搜索 + 已选 N 个 + 全选本页 + 移动到分组 + 删除 + 完成」共 7 个目标（截图 `temp/media-layout-verify-20261107/selection.png` 可复现）。
- 现象：模式切换（批量管理 ↔ 完成）和筛选条件是两种不同性质的控制，同排后一旦进入选择态，工具条宽度被撑满，筛选器仍占着左侧。
- 建议：入口移到页头 `actions`（与「新建分组 / 添加素材」同组），进入选择态后筛选器隐藏或收成只读摘要，工具条只保留「已选 / 全选 / 移动 / 删除 / 完成」。删除在右、完成在最右，现有顺序可保留。

### M10. 设置：三套分段控件外观并存

- 位置：主题三选一 `.preferences-themes`（34px，`settings.css:118-142`）、壁纸 Tab `.preferences-wallpaper-tabs`（30px，`settings.css:169-187`）、全局 `.segmented`（29px，`ui.css:90-102`）。
- 现象：同一屏上下相邻两组「看起来是分段控件、实际尺寸和圆角都不同」的控件（截图 `temp/settings-polish-20261107/settings-appearance.png`）；主题组是 `inline-grid` 宽度只包住内容，壁纸 Tab 是整行等分，宽度观感也不一致。
- 建议：主题组与壁纸 Tab 统一走 `.segmented.fitted`，高度取 30–32px，宽度都吃满内容列；主题项保留勾选图标即可，不必自定义 `min-height: 34px`。

### M11. 智能助手：输入框固定 34px，不能长文

- 位置：`features/ai/assistant.css:65-79`（`height/min-height/max-height` 都是 34px，`resize: none`）。
- 现象：多行长问题只能横向滚动看单行，与「对话输入」的预期不符；`rows={1}` 且无自动增高逻辑（`ai/module.tsx:140`）。
- 建议：`min-height: 34px; max-height: 160px; overflow-y: auto;`，输入时按 `scrollHeight` 增高（约 10 行封顶），发送后复位。不复用窗体 textarea 的 92px 起始高度。

### M12. 智能助手：页头在 624px 列内塞了标题 + 模型徽标 + 三个操作

- 位置：`features/ai/module.tsx:69-88`，`assistant.css:6`（`.chat-inner { max-width: 624px }`）。
- 现象：「智能助手」+ 模型 `badge` + 「保存到笔记」+「会话操作」+ 关闭 `X`。`.page-head-actions` 允许换行（`components.css:37`），标题块又带 `min-width: 0`，宽度不足时操作组会折行，标题与操作的行高不再对齐；1080 宽下这一行的余量已经很小。
- 建议：窄宽度时「保存到笔记」图标化（保 `aria-label` 与 `title`），或把它并入「会话操作」菜单——它作用于当前会话，归属上是合理的。关闭 `X` 保持最右独立位置不变。
